Know what a Bitcoin full node verifies

A node changes the verification path; it does not remove the need to secure a wallet or check the software you install.

Written and published 24 October 2026. Archive study date: 18 October 2026. This page does not claim it was available on the earlier date.

Read the primary guide

Original source. The Bitcoin.org full-node guide describes a full node as software that validates transactions and blocks. It also describes hardware, storage, bandwidth, and wallet-security considerations. Write down what the node checks for itself and what still depends on your device, configuration, and backups.

Map the trust path

Compare two hypothetical setups: a wallet that relies on another service for blockchain data, and a wallet connected to a node you operate. For each, note who supplies transaction history, who validates consensus rules, and where privacy or availability could fail. Do not assume that running a node automatically protects a compromised seed phrase.

Plan before installing

Check the current official download and requirements before committing disk space or connecting funds. Start with a test environment or small amount if learning. This exercise is about understanding verification, not recommending a particular wallet or operating setup.
