# Nakamoto Research website maintenance schedule

Updated 3 November 2026. Check every area on its cadence; edit only where evidence or a reader need warrants it. Record the result, outstanding work and deployment status. Never equate a date in a URL with an actual publication date.

## Daily

- Check original publishers for releases, corrections and scheduled events. Separate scheduled, provisional and published results.
- Publish useful News and Blog items when distinct evidence supports them. Label catch-up work with its real publication date.
- Review Trading Academy, Investing, Personal Finance and Bitcoin; improve a lesson, example, source route or reader path when needed.
- Update affected homepage routes, topic hubs, archives, search entries, source packs, RSS, sitemap and operation records.
- Check broken links, calculators and data-failure states. Inspect changed layouts on mobile and desktop, including keyboard navigation.
- Check deployment health and available traffic/indexing alerts. Report unavailable analytics rather than guessing results.
- Before sync: run local checks, review the diff and verify the intended deployment marker. After deployment: check live pages and assets.

## Weekly

- Review article coverage, corrections, reader questions and the next editorial queue. Historical gaps need a justified story, not filler.
- Improve at least one older guide, lesson, worksheet or calculator where there is a concrete weakness.
- Review all 40 section hubs for stale lead content, weak next steps and misplaced archive material.
- Check external source links and affiliate destinations; sample older high-traffic articles for accuracy.
- Review available search queries, indexing exclusions, top pages, newsletter delivery and reader behaviour.
- Verify recent deploys and backups, then record owners and deadlines for unresolved issues.

## Monthly

- Audit factual accuracy, duplicate/thin pages, titles, descriptions, canonicals, structured data, sitemap and feed.
- Test accessibility, keyboard use, contrast, mobile layouts, loading performance and important tools.
- Review Search Console, Bing Webmaster Tools, GA4 and Clarity when accessible. Keep observed results separate from targets.
- Review analytics behaviour, affiliate disclosures, newsletter forms, broken downloads and subscription costs.
- Check runtime/dependency updates and security notices. Test updates locally before deployment.
- Choose the next month's themes and prioritise work using reader needs and measured performance.

## Quarterly

- Review navigation, onboarding, learning paths and the usefulness of each major section.
- Consolidate overlapping content with intentional redirects where appropriate; preserve valuable history.
- Upgrade a weak section or major tool and validate it with readers when possible.
- Review account access, integrations and recovery contacts. Test restoring a backup in an isolated location.

## Yearly

- Verify domain, hosting, certificate and service renewal settings, billing contacts and ownership records.
- Review privacy, terms, editorial, affiliate and copyright policies against the site's actual behaviour; obtain qualified advice where necessary.
- Recheck evergreen financial guides, tax-year references, country guides and calculations against current original sources.
- Review account security, recovery methods, credentials, permissions and incident-response documentation.
- Perform an end-to-end recovery drill, including the repository, domain/DNS configuration and deploy settings.
- Review annual traffic, engagement, publishing quality, revenue and costs; set a funded roadmap with measurable goals.

## Definition of done

Source checked → useful edit → discovery updated → local checks passed → diff reviewed → authorised sync/deploy → live verification → operation record updated. If a step cannot be completed, name it explicitly; do not record it as passed.

After every publication, apply `POST_DEPLOYMENT_INSPECTION.md` and save the inspection result before reporting completion.
